# 200 项完整候选：描述精简 + FP8

用户约束：让模型直接在全部 200 项中选择；不按业务域在程序侧路由或筛选。每次请求保持候选 ID、候选顺序、业务状态和参考答案不变，仅改变描述的表达方式。测试结束只 stop GPU，不 terminate。

冻结后比较四组：

1. `original`：上一轮的中英混合长描述，作为同机同精度基线。
2. `concise-en`：英文单语言，保留动作与适用条件，删除重复表达。
3. `concise-zh`：中文单语言，保留动作与适用条件，删除重复表达。
4. `factored`：把十个业务域和二十类完整动作规则放在共同指令中，每个候选引用一个域和一个动作。所有 200 个候选仍交给模型；解释引用和选择均由模型完成，程序不做业务判断。

前三种逐项描述规则，第四种消除重复规则。第四种依赖本合成目录确实具有公共规则结构；不能推断 200 条完全不同的生产 SOP 也能得到相同比例的压缩。英文、中文精简是人工改写，不以字数减少推断 token 数减少或语义等价；由实际输入 token 和选择结果评估。

质量：原有 40 个合成快照，加 12 个在调用模型前冻结的规则优先级、边界与干扰测试，每例测原序及反序，共每组 104 次观察。新增测试是合成规则探针，不是生产样本。分别报告原有与新增测试的结果，保留全部错误。

性能：同一个 FP8 + Triton / Graphs 服务，每组单列 8 次预热；使用相同的 8 个原有快照做并发 1/2/4/8、每格 24 次请求的短时扫描。质量组原有快照的 P50/P95 用于描述对比；结束时复测基线的 16 次请求，检查时间漂移。结果缓存关闭，HTTP 客户端在同一 GPU 主机。

基线长描述超过 8192 tokens，仍走非 Graphs 路径；精简输入落在该范围内时可使用 Graphs。此次衡量同一启动配置下描述精简的整体效果，不把性能变化全部归因为 token 数，也不单独归因于 CUDA Graphs。

以各组实际 token、P50/P95、有效响应、参考一致率、100ms 内正确完成率、候选换序稳定性和并发吞吐判断结果。原有测试及报告保留。本轮数据独立保存于此目录。
