# H200 SOP验证计划

用户在风控四RTX验收完成后要求，下一阶段SOP测试全部使用H200。保持原始Karpo 4B、FP8按通道量化、完整200个候选、原始输入编码、双向全注意力和FP32决策输出头。

使用一台AWS八H200实例。每张GPU部署独立完整模型副本；本轮模型计算不使用RTX或H100。先比较最大活跃序列数1与4，以及1／2／4／8个GPU副本，记录完整质量、低负载和固定100 RPS过载/性能探测。所有配置都保留拒绝、超时和无效响应。

在通过质量与20秒100 RPS探测的配置中，优先选择GPU副本数最少的配置；同副本数选择探测P50较低者，再独立进行两轮120秒100 RPS确认。一次探测通过不能替代正式确认。

验收要求：

- 完整104条SOP合成质量观察的正确率超过90%，且没有无效请求。
- 两轮确认均各安排12,000个请求，每秒固定100个到达，不等待之前的响应。
- 两轮均零失败、端到端P50≤500ms、稳态有效吞吐≥99 RPS，无持续队列增长；压力样本正确率也须超过90%。
- 输入token数、token哈希和marker与原生基线逐条一致；启动时核对原始FP32输出头和实际GPU型号。

延迟从预定到达计算到完整HTTP响应，包含客户端调度滞后、编码、代理、队列和推理。压测驱动和模型位于同一H200主机，生产外部入口、特征查询及跨区域入口不在本轮计时内。与RTX结果比较时保留该链路差异。

现有SOP输入文件的104条样例均属于quality组；为保持与前轮相同输入，本轮压力测试循环复用这104条样例。质量测量和压力测量分别执行，但不是两个独立数据集，也不能据此推断真实生产数据准确率。

每2秒记录GPU利用率、显存与功耗；每阶段保存绝对UTC起止时间以及请求相对时间，便于对齐采样。Profiler时间不作为性能验收结果。

原实验输入与冻结证据保持不变，新测试使用独立目录。EC2继续保留，测试脚本仅结束自己创建的模型及监控进程，没有EC2自动关闭操作。已开通的八卡实例按整台计费，即使阶段仅启用其中部分GPU也不会减少实例费用。Spot参考价和实际资源另存于`results/instance.json`。
