# 六张RTX实际模型验证

用户明确要求“验证6卡”。本轮新增两张RTX PRO 6000 Blackwell Server Edition 96GB，优先与原四卡同在us-east-2c；当前区域Spot G/VT配额64 vCPU已占满，新增两台g7e.2xlarge使用按需计费。现有实例保留，测试后所有参与EC2继续运行。

容量核对后的部署修订：us-east-2三个可用区的g7e.2xlarge、4xlarge、8xlarge和12xlarge按需请求均失败，已有Spot扩额128 vCPU申请仍为CASE_OPENED。因此新增两张卡改用us-east-1的g7e.2xlarge Spot，保留原四卡及其他停止实例。最终市场、位置和成本以实际资源快照为准，先前按需费用仅为未实现方案的估算。跨区域模型端口仅通过SSH隧道访问，计入完整端到端延迟。

固定batch=4、CUDA Graph powers、FP8投影、原FP32决策头、完整双向注意力。每卡一个独立完整Karpo 4B副本，不做张量并行。保留上一轮原提示、全部200特征及六种候选动作，不压缩、裁剪或缓存答案，不重新调batch、提示或复核阈值。

逐字节复用上一轮review-baseline的1440条输入和真实编码参考，复用冻结复核阈值0.1628260940455841。原始answers保持不变，decision单独返回校准后的动作。质量阶段为1080请求；此为上一轮留出集的重复硬件验证，并非新的独立质量留出集，与tune仍共享45种合成模板。

验证顺序：核对六卡软硬件、权重与输出头；预热80请求；质量1080请求；40 RPS低负载20秒；100 RPS探测20秒；两轮各120秒持续100 RPS。固定速率调度，原始HTTP响应、真实编码、每卡GPU采样和计时均保留。

验收要求：质量全部尝试正确率≥90%；两轮正式压力均达到有效吞吐≥99 RPS、端到端P50≤500ms、零错误，同时检查尾段P50、发送滞后和积压趋势；压力正确率以全部尝试为分母且≥90%。不以拒绝请求减轻负载后宣称达标。

端到端从预定到达计至完整HTTP响应，包括调度、排队、编码、代理及实例间私网，不含生产外部入口及在线特征查询。加卡效果与四卡已封存结果对照，不能据此声称六卡为所有配置中的绝对最低。

完成后更新文档与HTML、独立核验、私有S3归档并推送GitHub。只管理本轮模型进程，不停止或终止EC2。
