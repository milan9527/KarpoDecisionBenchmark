# 固定batch的复核分数校准

用户要求不再调整batch，后续固定batch 4、CUDA Graph powers、四张原RTX副本。原输入的200个特征、原提示、FP8模型和FP32决策头均保留。

五种提示在360条tune上的正确率分别为：原提示79.17%、分条条件69.17%、自然语言条件67.50%、allow排除条件77.78%、平铺字段65.28%。提示修改没有改善效果，因此选择原提示。

随后仅用原提示tune的实际Karpo概率输出拟合一项复核阈值：

```text
score = p(review) / (p(review) + p(allow))
if raw_action == "allow" and score >= 0.1628260940455841:
    decision.action = "review"
else:
    decision.action = raw_action
```

原始`answers`不变；`decision`另外保存最终动作、原始动作、分数、阈值、是否升级及阈值文件hash。其他五种原始动作均不改变。分母为零时分数取零；不合法概率报错，不产生伪造有效答案。

阈值选择约束为tune正常样本误干预率不超过1%，在候选阈值中优先最大化全部请求正确率，再依次减少作弊放行、正常误干预，并取较高阈值。选定阈值的tune正确率356/360（98.89%），review正确85/88，正常误干预0/112。

阈值于2026-11-21 03:49:36.762319 UTC冻结，新留出集第一次推理始于03:50:09.666723 UTC。`review-calibration-v1.json`记录调参源文件hash、完整阈值候选与选择结果；复核器校验源码hash、重新计算阈值选择，并检查冻结早于留出集推理。

新留出集1080次请求由540个新实体案例的两种候选顺序组成，与tune共享45种合成场景模板。第一次留出集原始输出离线应用冻结阈值得到1063/1080（98.43%），review正确251/264，正常误干预0/336，作弊放行1/408。这是离线结果；最终结论取独立实际HTTP服务测试，见[正式结果](RESULTS.zh.md)。

实际HTTP验证保持同四个模型副本，增加CPU后处理，不增加模型调用。质量阶段与两轮120秒100 RPS压测分别统计原始Karpo选择和最终决策，错误或限流均计入全部尝试分母。质量改善不意味着GPU容量改善，也不表示整体性能验收通过。

本方法属于模型分数后处理，没有重新训练模型，不应将最终决策正确率表述为原始模型argmax准确率。阈值尚未经过真实业务分布、漂移与成本验证，合成结果不能直接替代生产验收。
