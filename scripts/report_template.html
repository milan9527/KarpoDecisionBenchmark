瓶颈在服务端串行推理

官方服务使用 Runner 锁串行处理模型推理。FP8 并发从 1 增至 8，吞吐仍约为 @@THROUGHPUT@@ 请求/秒，P95 则升至 @@C8_P95@@ 秒。

增加 HTTP worker 不能直接视为 GPU 推理吞吐提升。不同请求需要限制排队、设置截止时间，并验证多副本或真正的批处理方案。

Server-Timing: model
包含 Runner 锁等待，不是纯 GPU kernel 耗时。
